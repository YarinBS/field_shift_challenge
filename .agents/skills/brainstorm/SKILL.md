# Brainstorm

## Procedure

1. Clarify the question and inspect only the relevant project context and documentation.
2. Generate multiple viable alternatives rather than jumping to implementation.
3. Compare scientific validity, data availability, implementation complexity, feasibility,
   risks, dependencies, and hackathon time constraints.
4. Challenge weak assumptions and distinguish verified facts from hypotheses.
5. Recommend one approach with explicit trade-offs.

For significant decisions, present the alternatives and recommendation, then wait for
approval before treating the recommendation as a project decision or editing code/docs.
Ask focused clarification questions when missing information materially changes the answer.

## Success criteria

The result contains actionable alternatives, risks, evidence, and a reasoned recommendation;
it does not silently commit an unapproved architecture or feature decision.
