# Explain code

Start with the component's purpose and its place in the architecture. Trace the execution
flow through important functions, data structures, interfaces, and frontend/backend/model
boundaries. Explain relevant design decisions, alternatives, assumptions, and limitations.
Use code and documentation as evidence and adapt depth to the question.

Distinguish current behavior from planned behavior and identify what a contributor should
understand before modifying the component. Do not invent runtime behavior that was not
verified.

## Success criteria

The explanation is accurate, traceable to repository code, clear about uncertainty, and useful
for safely making the next change.
